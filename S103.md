## Resumen

En esta clase se estudió la teoría sobre el modelado de datos mediante el *Modelo Relacional* y el *Modelo Estrella*.

Los elementos fundamentales del análisis de datos en modelos relacionales son las tablas, compuestos de columnas (campos o ejes de datos) y las filas (registros u observaciones), las cuales se pueden enlazar con otras tablas para formar relaciones de dominio para profundizar el análisis de los datos.

Las tablas pueden ser vistas como modelos y las columnas de la tabla/modelo podrán ser conectadas con otras columnas bajo una relación y restricción.

### Modelo de datos

> Estructurar de las tablas

	TABLA DE HECHOS - La tabla más fina posible para un análisis específico
	TABLA DIMENSIONAL - Una tabla de soporte que extiende información no específica

1. Dimensión:

		¿Cuántos registros hay? Muchos - Profunda / Pocas - Regiones/Locaciones
		Ejemplo: Tabla calendario
		Profunda: Por día
		Regional/Local: Por Mes / Por Trimestre / Por Año
	
		Ejemplo: Tabla pagos
		Profunda: # de Pago
		Regional/Local: Por Sucursal / Por Vendedor / Por Venta / Por Mes / ...

2. Granularidad:
	
		¿Qué tan finos son los datos? Muchos - Fino/Particular / Pocos - Grueso/General
		Ejemplo: Tabla de ventas (Reginal/Local)
		Agrupación por vendedores para saber el promedio de venta:
			[Fino a lo Grueso] - Análisis en Granularidad (De lo particular a lo general)
			Muchas ventas se agrupan en pocos vendedores (promedio venta.total)

		Ejemplo: Tabla de ventas (Reginal/Local)
		Crecimiento en ventas de cada vendedor:
			[Grueso a lo Fino] - Análisis en Finitud (De lo general a lo particular)
			Muchas ventas se agrupan en pocos vendedor
			Pocos vendedores se desmenuzan en muchas ventas (vendedor.promedioTotalVenta)

### Compración de granularidad entre tablas

La comparación entre las grunalidades de las tablas permite establecer quién sumará o se agregará y quién se desglosará o desmenuzará para rellenar datos replicados.

> Ejemplo de granularidad entre tablas

	Pagos (Muchos) / Ventas (Pocos)
	
	Fino: Pagos
	Muchos Pagos Agregan Pocas Ventas
	(Aglomerar/Agrupar/Sintetizar)
	
	Grueso: Ventas
	Pocas Ventas Rellenan Muchos Pagos
	(Desmenuzando)
	
	Una tabla de hechos se construye
	con los datos más finos posibles
	para responder un ANÁLISIS ESPECÍFICO
	
	Una tabla dimensiona se relaciona con
	una tabla de hechos para formar reportes
	extendidos de interés 
	en un ANÁLISIS NO ESPECÍFICO
